Welcome to Trinity

Trinity is a decentralized, open-source AI agent for the Morpheus Network. This onboarding wizard will walk you through:

  • Installing Docker — the runtime for every Trinity service.
  • Spinning up the Trinity container — the sandboxed agent process.
  • Spinning up the Trinity Brain container — memory, vectors, graph.
  • Installing the Bridge — the host-side gatekeeper that guards access to your computer.
  • Configuring the agent — API keys, permissions, the first hello.
Architecture. The Trinity agent lives in an isolated Docker container and cannot touch your computer directly. Every request to read a file, run a shell command, or reach a device flows through the Bridge, which runs on your host and enforces the permissions you configure here.

System Requirements

Before we begin, make sure your host satisfies the following:

OS

Windows 10/11, macOS 12+, or Linux (kernel 5.10+)

CPU

4+ cores (8+ recommended for local LLMs)

Memory

16 GB RAM minimum · 32 GB recommended

Disk

40 GB free (models + vector/graph stores)

Node.js

v20+ on the host (needed by the Bridge)

Network

Outbound HTTPS for pulling images & model weights

Install Docker

Trinity runs as a set of Docker containers. Pick your platform for a copy-paste install script, or install Docker Desktop manually. 

# Install Docker Engine + Compose (Ubuntu/Debian)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# re-login, then verify:
docker --version
docker compose version
# Install Docker Desktop (Homebrew)
brew install --cask docker
open -a Docker
# Wait for whale icon, then verify:
docker --version
docker compose version
# Install Docker Desktop (winget)
winget install Docker.DockerDesktop
# Enable WSL2 backend when prompted, then in PowerShell:
docker --version
docker compose version

Install the Bridge

The Bridge runs on your host (not in Docker) and is the only channel between the Trinity container and your computer. It enforces the allow-lists you configure on the Access Control page.

Why a bridge? Giving a container raw access to your host (Docker socket, the filesystem, devices) defeats the purpose of containerising it. The bridge exposes a narrow, audited API over localhost, and every request is logged and permission-checked.

1. Install dependencies

cd webapp/bridge
npm install

2. Start the Bridge

# Runs on http://127.0.0.1:4711 by default
node bridge-server.js

# Or install as a background service:
node bridge-server.js --daemon

3. Pair the webapp with the Bridge

Trinity's Wallet

Trinity needs her own blockchain identity. This step creates an HD wallet (BIP-39 mnemonic) that lives encrypted inside the agent's container.

How addresses are used. Address #0 is Trinity's main gateway address — used for opening the primary Morpheus compute session (staking MOR). Addresses #1, #2, … are for sub-agents that need their own sessions with different LLM providers. Trinity manages these internally and derives them from the same master mnemonic as needed.
